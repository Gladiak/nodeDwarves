# Narrative Event Contract v1

Status: `Approved for implementation`

This document is the normative contract for NodeDwarves narrative events. It closes Epic Evolution
step E0.2 and defines the target behavior for E0.3 tests and the E1.1 event-core implementation.
It does not authorize simulation, balance, observation-shape, or policy changes by itself.

## 1) Goals and boundaries

The event substrate must:

- produce deterministic, machine-readable facts from the existing simulation order;
- keep current string-only `pushEvent` callers working during incremental migration;
- preserve the compact HUD mini-log and current Event Log panel behavior;
- carry stable actor and causal references without retaining live state objects;
- remain plain-JSON, bounded, and safe for reports and future Chronicle tooling;
- avoid changing simulation decisions, random-number consumption, AI observations, or actions.

The event substrate is not:

- a save-game format;
- an unbounded history of the world;
- a replacement for simulation state;
- a source of wall-clock timestamps or random identity;
- permission to expose narrative state to PPO training.

## 2) Versioned event envelope

Every newly emitted structured event uses `schemaVersion: 1` and the following canonical shape.
Fields marked nullable are present with `null` when no value exists. Bounded arrays are always present.

```js
{
  schemaVersion: 1,
  id: 'evt:v1:c0000:t0000000963:s0002',
  cycle: 0,
  tick: 963,
  sequence: 2,
  type: 'lifecycle.birth',
  category: 'lifecycle',
  importance: 'notable',
  message: 'Birth: Dori Ironhand joins the settlement',
  actors: [
    {
      kind: 'dwarf',
      id: 'dwarf_1042',
      role: 'primary',
      label: 'Dori Ironhand'
    }
  ],
  location: {
    scope: 'surface',
    depth: 0,
    x: 42,
    y: 17,
    placeId: null,
    label: null
  },
  causes: [
    {
      kind: 'state',
      ref: 'population.reproduction',
      metric: null,
      value: null
    }
  ],
  consequences: [
    {
      kind: 'create',
      targetKind: 'dwarf',
      targetId: 'dwarf_1042',
      metric: null,
      value: null,
      unit: null
    }
  ],
  sagaId: null,
  source: 'population',
  tags: ['birth']
}
```

Generated fields are `schemaVersion`, `id`, `cycle`, `tick`, and `sequence`. Producers must not
control them. A producer supplies narrative facts; the event core supplies ordering and identity.

### 2.1 Core scalar fields

| Field | Contract |
| --- | --- |
| `schemaVersion` | Integer `1`. Other versions require an explicit reader/migration path. |
| `id` | Generated deterministic ID described in section 5; maximum 96 UTF-8 bytes. |
| `cycle` | Non-negative integer from `state.cycleStats.count`, defaulting to `0`. |
| `tick` | Non-negative integer from `state.tick`, defaulting to `0`. |
| `sequence` | Non-negative per-tick event sequence generated by the event clock. |
| `type` | Lowercase semantic token, maximum 64 bytes; use a namespace such as `combat.raid_end`. |
| `category` | One value from the closed category set in section 3. |
| `importance` | `ambient`, `notable`, `major`, `critical`, or `legendary`. |
| `message` | Required trimmed display text, 1-512 UTF-8 bytes, with no ANSI control sequences. |
| `sagaId` | Nullable stable saga reference, maximum 96 bytes. Ordinary producers leave it `null` until the Story Director owns saga assignment. |
| `source` | Lowercase producer/system token, maximum 64 bytes. |
| `tags` | Sorted unique lowercase tokens, maximum 8 entries and 32 bytes per entry. |

`type`, `source`, producer-owned IDs, roles, tags, metrics, and units use tokens matching
`^[a-z0-9]+(?:[._-][a-z0-9]+)*$`. Generated event IDs use the colon-delimited format in section 5;
an event-kind cause reference therefore follows that event-ID format instead of the general token
rule. Human-readable text belongs in `message` or optional `label` fields, not in identifiers.

Human-readable strings are normalized by removing ANSI sequences, replacing control characters and
line breaks with spaces, collapsing repeated whitespace, trimming, and then truncating on a valid
UTF-8 boundary. Token fields are trimmed and lowercased. An invalid core token uses its documented
fallback; an invalid nested reference is discarded rather than partially guessed.

### 2.2 Actor references

`actors` contains at most 8 compact references. It never contains a dwarf, structure, camp, or other
live state object.

```js
{
  kind: 'dwarf',
  id: 'dwarf_1042',
  role: 'primary',
  label: 'Dori Ironhand'
}
```

- `kind` is one of `dwarf`, `faction`, `settlement`, `structure`, `location`, `camp`, `caravan`,
  `threat`, `wildlife`, `artifact`, `institution`, or `system`.
- `id` is required and limited to 96 bytes.
- `role` is one of `primary`, `secondary`, `instigator`, `target`, `victim`, `ally`, `opponent`,
  `leader`, `member`, `beneficiary`, `witness`, `owner`, `founder`, `parent`, or `child`.
- `label` is an optional immutable display snapshot limited to 120 bytes. It keeps old events readable
  after death or cycle reset; `kind + id`, not the label, is the authoritative identity.
- Duplicate `kind + id + role` references keep their first occurrence.
- Producers preserve semantic order and place the primary subject first when one exists.

Future identity resolvers may enrich rendering from the ID, but they must fall back to `label` and
must not mutate the stored event.

### 2.3 Location reference

`location` is always present and has one of three scopes:

```js
{ scope: 'world', depth: null, x: null, y: null, placeId: null, label: null }
{ scope: 'surface', depth: 0, x: 42, y: 17, placeId: null, label: 'East Gate' }
{ scope: 'underrealm', depth: 3, x: null, y: null, placeId: 'deep_lift', label: null }
```

- `scope` is `world`, `surface`, or `underrealm`.
- `world` forces `depth`, `x`, and `y` to `null`.
- `surface` forces `depth` to `0`.
- `underrealm` requires an integer `depth >= 1`.
- Coordinates are optional, non-negative integers and are accepted only as a complete `x/y` pair.
- `placeId` is nullable and limited to 96 bytes; `label` is nullable and limited to 120 bytes.
- Invalid or incomplete locations normalize to the world-scoped default.

Coordinates are historical facts only. Consumers must not assume that a referenced tile or entity
still exists in the current cycle.

### 2.4 Cause references

`causes` contains at most 8 entries:

```js
{
  kind: 'event',
  ref: 'evt:v1:c0000:t0000000950:s0000',
  metric: null,
  value: null
}
```

- `kind` is `event`, `state`, `action`, or `threshold`.
- `ref` is a required token limited to 96 bytes. Event causes use an event ID; other causes use a
  stable path or action name such as `stockpile.food_ratio` or `expedition.dispatch`.
- `metric` is a nullable token limited to 64 bytes.
- `value` is a nullable JSON scalar: finite number, boolean, or string limited to 120 bytes.
- Duplicate normalized entries keep their first occurrence.

Cause references describe why an event happened; they do not duplicate the source state object.

### 2.5 Consequence facts

`consequences` contains at most 12 entries:

```js
{
  kind: 'delta',
  targetKind: 'resource',
  targetId: 'stockpile.food',
  metric: 'amount',
  value: -12,
  unit: 'units'
}
```

- `kind` is `delta`, `status`, `progress`, `create`, `destroy`, `death`, `injury`, `transfer`, or
  `unlock`.
- `targetKind` uses the actor-kind set extended with `resource` and `world`.
- `targetId` is required and limited to 96 bytes.
- `metric` and `unit` are nullable tokens limited to 64 and 32 bytes respectively.
- `value` follows the bounded JSON-scalar rule used by causes.
- Duplicate normalized entries keep their first occurrence.

Consequences are descriptive facts emitted after the simulation has already applied the change.
Narrative consumers must never replay them as commands against simulation state.

## 3) Closed enums and defaults

The v1 category set preserves every category currently inferred by `src/simulation/events.js`:

```text
social lifecycle schism festival myth warrior diplomacy combat
underrealm economy world other
```

The existing drama filter remains exactly:

```text
social lifecycle schism festival myth warrior underrealm
```

Normalization uses these fallbacks in order:

1. valid explicit producer value;
2. legacy message-prefix inference where it already exists;
3. the safe fallback below.

| Field | Safe fallback |
| --- | --- |
| `category` | `other` |
| `type` | `legacy.<category>` |
| `importance` | config mapping by type, then category, then `ambient` |
| `source` | normalized category |
| `location` | world-scoped null location |
| `actors`, `causes`, `consequences`, `tags` | empty bounded array |
| `sagaId` | `null` |

Importance mappings belong in `config.json` when E1.1 implements them; no producer or renderer may
hide tuning defaults in a private constant. E0.2 adds no config parameter because it defines only the
contract.

The E1.1 config shape is:

```json
{
  "events": {
    "importance": {
      "default": "ambient",
      "byCategory": {},
      "byType": {}
    }
  }
}
```

Resolution order is `byType[type]`, `byCategory[category]`, `default`, then the contract fallback
`ambient`. E1.1 must provide explicit sensible defaults and document them in `docs/PARAMETERS.md`.

## 4) Producer API and normalization

E1.1 must keep both producer forms:

```js
pushEvent(state, config, 'Birth: dwarf_1042 joined the settlement');

pushEvent(state, config, {
  type: 'lifecycle.birth',
  category: 'lifecycle',
  importance: 'notable',
  message: 'Birth: Dori Ironhand joins the settlement',
  actors: [{ kind: 'dwarf', id: 'dwarf_1042', role: 'primary', label: 'Dori Ironhand' }],
  source: 'population',
  tags: ['birth']
});
```

The existing transitional form also remains valid:

```js
pushEvent(state, config, 'Message', { category: 'world', source: 'weather' });
```

The function returns the normalized v1 event on success and `null` on rejection. Existing callers
that ignore the return value remain valid. The object form must not be combined with a `details`
argument.

Producer-supplied generated fields are ignored and replaced by core-generated values. Non-array
collection fields normalize to empty arrays. Collections discard invalid entries, deduplicate as
defined by their schema, and keep the first allowed number of valid entries; tags are sorted before
their final eight-entry cap. Overlong optional labels/scalar strings are safely truncated, while an
overlong or invalid required nested ID causes that nested entry to be discarded. Non-finite numeric
values are discarded. Coordinates and generated counters must also be safe integers.

Normalization order is deterministic:

1. validate the state/config container and select string or object input;
2. trim and validate `message`; reject an empty message before allocating a sequence;
3. normalize category, type, importance, source, and nullable saga reference;
4. normalize bounded actor, location, cause, consequence, and tag values;
5. peek the candidate cycle/tick/sequence and construct the candidate event ID without advancing the
   event clock;
6. verify plain-JSON serialization, the byte ceiling, and retained-ID uniqueness;
7. commit the candidate sequence to the event clock;
8. append the message to the HUD mini-log;
9. expose the normalized event to future synchronous narrative consumers;
10. append it to the bounded structured Event Log buffer;
11. return the normalized event.

Steps 7-9 must not consume randomness or invoke simulation mutations. Rejected inputs do not consume
a sequence and do not update either log.

Migrated structured producers must supply explicit `type`, `category`, and `source`. Fallbacks exist
for compatibility and malformed-input safety, not as a substitute for producer migration.

### 4.1 Legacy read compatibility

Current stored entries shaped as `{ tick, message, category, source }` are schema v0 display records.
`normalizeEventLogEntry` must continue to read them without mutating state or allocating an event ID.
It returns display-safe defaults and may expose `schemaVersion: 0` and `id: null` to distinguish them.

String entries in `state.events` receive the same read-only display treatment. A renderer must never
invent a persistent ID from array position because retention changes that position over time.

No eager in-memory migration is required. Events emitted after E1.1 are v1; older retained entries
age out naturally under the configured Event Log cap.

## 5) Deterministic identity and ordering

State owns an event clock independent of retained log length:

```js
state.eventClock = {
  tick: -1,
  nextSequence: 0
};
```

For every event candidate:

1. resolve `cycle = floor(max(0, state.cycleStats.count || 0))`;
2. resolve `tick = floor(max(0, state.tick || 0))`;
3. when the stored clock tick differs, peek sequence `0`; otherwise peek `nextSequence`;
4. use the peeked sequence to construct and validate the candidate event;
5. only after acceptance, store the current tick and set `nextSequence = sequence + 1`;
6. format `evt:v1:cCCCC:tTTTTTTTTTT:sSSSS`.

`CCCC`, `TTTTTTTTTT`, and `SSSS` are minimum widths of 4, 10, and 4 digits. Values expand instead of
wrapping. Example: cycle 3, tick 81, second accepted event becomes
`evt:v1:c0003:t0000000081:s0001`.

Identity never depends on:

- `Math.random()` or any seeded RNG draw;
- `Date`, elapsed time, terminal size, or render cadence;
- message text, actor labels, coordinates, or object-key order;
- the current length of `state.events` or `state.eventLog`.

The guarantee is: equal initial state, config, seed, code version, and event-emission order produce
equal IDs and ordering. IDs are not promised to remain identical after a code change deliberately
adds, removes, or reorders events.

The cycle counter must be installed on a newly reset state before that state may emit events. A
duplicate ID in retained narrative state is a contract violation: reject the event, increment a
diagnostic collision counter, and fail deterministic contract tests. Do not silently add a random or
content-derived suffix.

## 6) Bounded storage and retention ownership

The stores have separate purposes and limits:

| Store | Payload | Owner/config | Purpose |
| --- | --- | --- | --- |
| `state.events` | message strings | `events.maxEntries`, currently `5` | compact HUD mini-log |
| `state.eventLog` | full v1 events plus aging v0 records | `events.logMaxEntries`, currently `300` | scrollable Event Log UI |
| future active story state | event IDs and bounded active-saga facts | Story Director config | current narrative focus |
| future Chronicle/deeds | compact facts plus source event IDs | Chronicle config | durable in-cycle history |
| future cycle legacy | bounded summaries and provenance IDs | legacy config | cross-cycle memory |

Rules:

- Limits are non-negative integers; `0` disables retention for that store.
- Both current logs retain newest-first ordering and trim immediately after append.
- `eventClock` never derives sequence state from either retained array.
- Normalization still returns a v1 event when `logMaxEntries` is `0`, allowing future bounded
  consumers to observe it before the UI buffer discards it.
- Chronicle and legacy systems must not copy full event objects indefinitely. They store bounded facts
  and source IDs under their own config caps.
- A missing source event after Event Log trimming is valid. The Chronicle fact must remain readable
  from its own compact payload and retain the source ID as provenance.

This separation prevents the UI buffer from becoming an accidental save file and prevents future
history from growing with total simulation ticks.

## 7) Serialization contract

Every v1 event must survive `JSON.parse(JSON.stringify(event))` without semantic loss.

Forbidden values include:

- `undefined`, `NaN`, `Infinity`, `-Infinity`, `BigInt`, functions, and symbols;
- `Map`, `Set`, class instances, circular references, buffers, and live state references;
- ANSI escape sequences and renderer-specific color/style objects;
- wall-clock timestamps, host paths, terminal dimensions, or process-specific identifiers.

Strings are UTF-8. Limits in this document are UTF-8 byte limits, not JavaScript code-unit counts.
After field normalization, one serialized event has a hard ceiling of 16 KiB. If a draft exceeds the
ceiling, the normalizer deterministically removes optional data in this order:

1. actor labels;
2. location label;
3. cause values;
4. consequence values;
5. trailing causes;
6. trailing consequences;
7. trailing secondary actors;
8. trailing tags.

It then adds the reserved tag `contract_truncated` when space permits, replacing the final tag when
the tag cap is already full. If the required core still
does not fit, the event is rejected before sequence allocation. Tests must cover both outcomes.

Tags are lexically sorted after normalization. Other arrays preserve producer order. Object key order
is never semantically significant.

### 7.1 AI, reports, and exports

- E0-E3 keep AI observation/action shapes unchanged. `state.eventLog`, `eventClock`, story, and
  Chronicle state must not enter `src/ai/observation.js` without a separately approved compatibility
  decision and fresh-training assessment.
- Headless benchmark and regression reports may aggregate scalar event counts but must not serialize
  unbounded event arrays.
- The current map export snapshot intentionally contains only structures, roads, temple, and
  Underrealm metadata; E1.1 must not add events to it.
- Report fixtures must use deterministic simulation tick/cycle fields, never generation time as event
  identity.

## 8) Versioning rules

- Adding an optional field with a deterministic default may remain schema v1.
- Changing ID semantics, required fields, enum meaning, ordering, or normalization behavior requires
  a version decision and compatibility tests.
- Readers accept known versions and adapt v0 display records; unknown future versions must degrade to
  a safe message/category display instead of crashing the Event Log.
- Writers emit only the active schema version. They never downgrade a structured event to v0.
- Schema upgrades must document whether old IDs remain authoritative; IDs are never rewritten merely
  for display convenience.

## 9) Required diagnostics and invariants

E1.1 should maintain bounded scalar diagnostics for at least:

```text
accepted rejected legacyNormalized truncated collisions
```

Diagnostics must not include unbounded per-message samples. The core invariants are:

1. no accepted event has an empty message or invalid enum;
2. accepted IDs are unique within the run and monotonic by `(cycle, tick, sequence)`;
3. string-only callers still update the mini-log and render through the Event Log;
4. all nested data is plain JSON and respects declared limits;
5. retained arrays never exceed configured caps;
6. event emission consumes no random draw and changes no simulation decision;
7. equal seeded runs produce equal event IDs/order;
8. all current Event Log categories and the drama filter remain compatible;
9. AI observation/action shapes and map-export payload remain unchanged.

## 10) E0.3 acceptance matrix

E0.3 turns the canonical contract and existing compatibility boundaries into executable fixtures.

| Test lane | Required evidence |
| --- | --- |
| valid structured event | canonical v1 shape, defaults, actor/location/cause/consequence bounds |
| legacy string caller | mini-log and Event Log compatibility, inferred category, `legacy.*` type |
| malformed input | empty-message rejection, enum fallback, invalid nested-value removal |
| deterministic identity | equal runs produce equal IDs; multiple same-tick events increment sequence |
| cycle reset | next-cycle IDs use the installed cycle counter and cannot collide |
| retention | both log caps including `0`; event clock remains independent of trimming |
| serialization | JSON round trip, UTF-8 byte limits, and strict oversize rejection; E1.1 adds deterministic draft reduction tests when the normalizer exists |
| renderer compatibility | all/drama filters accept v0 and v1 entries without mutation |
| non-regression | no RNG consumption, unchanged AI shapes, unchanged map-export schema |

The focused gate is `npm run test:narrative`, and `npm test` runs it before the existing
training/validation contracts. E1.1 must extend the suite to assert actual structured `pushEvent`
outputs, configured importance fallback, deterministic oversize draft reduction, collision
diagnostics, and returned-event behavior. E1.1 is not complete until those integration assertions and
the existing E0.3 lanes pass together.

## 11) Current-system audit

E0.2 reviewed the existing event path before choosing this contract:

- `src/simulation/events.js` currently writes strings to `state.events` and four-field records
  (`tick`, `message`, `category`, `source`) to `state.eventLog`.
- `src/simulation/narrative_contract.js` now provides strict v1 validation and transactional identity
  helpers, but E0.3 deliberately does not connect them to runtime emission.
- Existing simulation producers are overwhelmingly string-only, so an all-at-once migration would be
  unnecessary risk.
- `src/render/event_log_panel.js` reads only tick/message/category and preserves all/drama filters.
- Telemetry consumes compact message strings, not structured events.
- AI observation and action code does not consume either event buffer.
- The map-export snapshot excludes both event buffers.
- The long E0.1 probe reached the `300`-entry per-seed Event Log cap, confirming that UI retention
  cannot serve as permanent history.

These facts justify a compatibility normalizer, deterministic generated identity, and separate
retention ownership for Event Log, Story Director, Chronicle, and cross-cycle legacy.
